python-ocpp-sdk

Async Python SDK for OCPP-J (OCPP over JSON/WebSocket), for both the Charge Point / Charging Station and Central System / CSMS roles. PyPI name ocpp-sdk, import ocpp_sdk, Python 3.11+, MIT licence.

Pre-alpha: the core, transport and OCPP 1.6 message models exist; items marked "planned" do not.

Transport

ocpp_sdk.transport is version-agnostic. A Server and a Client hand every received text frame to a sink (anything with feed(raw) and async close(); ocppj.Endpoint is one).

import asyncio

from ocpp_sdk.transport import Client, Connection, Server


class Printer:
    def __init__(self, name: str) -> None:
        self.name = name

    def feed(self, raw: str) -> None:
        print(self.name, "received", raw)

    async def close(self) -> None:
        pass


async def main() -> None:
    async def csms_connect(conn: Connection) -> Printer:
        return Printer("csms")

    async def station_connect(conn: Connection) -> Printer:
        return Printer("station")

    async with Server(csms_connect, port=0) as server:
        url = f"ws://127.0.0.1:{server.port}/ocpp/CP001"
        async with Client(url, station_connect) as client:
            assert client.connection is not None
            await client.connection.send('[2,"1","Heartbeat",{}]')
            await asyncio.sleep(0.1)


asyncio.run(main())
  • The charge point ID is the last URL path segment (1-48 characters, no : or /). An invalid or unknown ID (known_id) answers HTTP 404.
  • The server picks the version by its own order of preference among the subprotocols the client offers (ocpp1.6, ocpp2.0.1, ocpp2.1). With no common one the handshake completes and the connection is closed with 1002.
  • A second connection with the same ID replaces the first (closed with 1008).
  • Compression is off, binary frames are refused (1003), ping every 30 s with a 10 s timeout, messages up to 1 MiB (1009 above that).
  • Server.shutdown(timeout) closes every connection with 1001, and a handshake that finishes during shutdown is closed with 1001 too.
  • Client reconnects as in OCPP-J section 5.4 (Reconnect(wait_minimum=1, random_range=2, repeat_times=6)): the wait applies after every lost connection and failed attempt, doubles up to repeat_times times, and resets after a successful connection. A missing common subprotocol counts as a failed attempt. reconnect=None makes one attempt.

Core

  • ocpp_sdk.errors: OCPPError and its subclasses CallTimeoutError, NotConnectedError, QueueFullError, ValidationError and CallError; code sets ErrorCodeV16 (1.6 spelling) and ErrorCodeV2 (2.0.1 and 2.1).
  • ocpp_sdk.datetime: parse and format for every version. Naive datetimes are rejected.
  • ocpp_sdk.ocppj: Endpoint correlates calls, enforces timeouts (30 s from send), sends one CALL at a time with a bounded queue of 1,000, answers handler errors with InternalError (the exception text is never sent), and fails waiting calls with NotConnectedError when the connection ends. Nothing is queued or retried while offline.

OCPP 1.6 messages

The message models are generated from the official JSON schemas by tools/gen and are Pydantic v2 models. Python attributes are snake_case, the wire names are the spec's camelCase. Requests are <Action>Request and answers <Action>Confirmation; every class has an ACTION class variable. Enums are StrEnums with the spec's values.

Shared datatypes and enums are in ocpp_sdk.v16.types. The 1.6 security extension messages are planned.

from ocpp_sdk.v16 import new_registry
from ocpp_sdk.v16.core import BootNotificationConfirmation, BootNotificationRequest
from ocpp_sdk.v16.types import RegistrationStatus

registry = new_registry()
request = BootNotificationRequest(charge_point_vendor="Acme", charge_point_model="X1")
registry.encode(request)  # {'chargePointVendor': 'Acme', 'chargePointModel': 'X1'}

answer = registry.decode_response(
    "BootNotification",
    {"status": "Accepted", "currentTime": "2025-01-02T03:04:05Z", "interval": 300},
)
assert isinstance(answer, BootNotificationConfirmation)
assert answer.status is RegistrationStatus.ACCEPTED

Incoming messages are validated on decode and outgoing ones on encode. Unknown properties are ignored (real stations send extras); everything else the schemas reject is rejected, plus the clear rules of the spec text: connectorId ranges, meterValue and chargingSchedulePeriod not empty, the first charging period starting at 0, charging limits with at most one decimal, a RemoteStartTransaction profile of purpose TxProfile, unique idTags (ignoring case) in SendLocalList with idTagInfo on every entry of a Full update, and absolute URIs for GetDiagnostics and UpdateFirmware. Naive datetimes are rejected; timestamps are sent in UTC with Z. An invalid incoming call is answered with the CALLERROR code that fits (1.6 spelling, OccurenceConstraintViolation included) and the offending field path.
