python-ocpp-sdk

Async Python SDK for OCPP-J (OCPP over JSON/WebSocket), for both the Charge Point / Charging Station and Central System / CSMS roles. PyPI name ocpp-sdk, import ocpp_sdk, Python 3.11+, MIT licence.

Pre-alpha: the core, transport and OCPP 1.6 message models exist; items marked "planned" do not.

Install

pip install ocpp-sdk   # Python 3.11 or newer; depends on pydantic 2 and websockets

Not on PyPI yet: the first release is planned. Until then install from the repository (pip install git+https://github.com/foecum/python-ocpp-sdk).

Transport

ocpp_sdk.transport is version-agnostic. A Server and a Client hand every received text frame to a sink (anything with feed(raw) and async close(); ocppj.Endpoint is one).

import asyncio

from ocpp_sdk.transport import Client, Connection, Server


class Printer:
    def __init__(self, name: str) -> None:
        self.name = name

    def feed(self, raw: str) -> None:
        print(self.name, "received", raw)

    async def close(self) -> None:
        pass


async def main() -> None:
    async def csms_connect(conn: Connection) -> Printer:
        return Printer("csms")

    async def station_connect(conn: Connection) -> Printer:
        return Printer("station")

    async with Server(csms_connect, port=0) as server:
        url = f"ws://127.0.0.1:{server.port}/ocpp/CP001"
        async with Client(url, station_connect) as client:
            assert client.connection is not None
            await client.connection.send('[2,"1","Heartbeat",{}]')
            await asyncio.sleep(0.1)


asyncio.run(main())
  • The charge point ID is the last URL path segment (1-48 characters, no : or /). An invalid or unknown ID (known_id) answers HTTP 404.
  • The server picks the version by its own order of preference among the subprotocols the client offers (ocpp1.6, ocpp2.0.1, ocpp2.1). With no common one the handshake completes and the connection is closed with 1002.
  • A second connection with the same ID replaces the first (closed with 1008).
  • Compression is off, binary frames are refused (1003), ping every 30 s with a 10 s timeout, messages up to 1 MiB (1009 above that).
  • Server.shutdown(timeout) closes every connection with 1001, and a handshake that finishes during shutdown is closed with 1001 too.
  • Client reconnects as in OCPP-J section 5.4 (Reconnect(wait_minimum=1, random_range=2, repeat_times=6)): the wait applies after every lost connection and failed attempt, doubles up to repeat_times times, and resets after a successful connection. A missing common subprotocol counts as a failed attempt. reconnect=None makes one attempt.

Core

  • ocpp_sdk.errors: OCPPError and its subclasses CallTimeoutError, NotConnectedError, QueueFullError, ValidationError and CallError; code sets ErrorCodeV16 (1.6 spelling) and ErrorCodeV2 (2.0.1 and 2.1).
  • ocpp_sdk.datetime: parse and format for every version. Naive datetimes are rejected.
  • ocpp_sdk.ocppj: Endpoint correlates calls, enforces timeouts (30 s from send), sends one CALL at a time with a bounded queue of 1,000, answers handler errors with InternalError (the exception text is never sent), and fails waiting calls with NotConnectedError when the connection ends. Nothing is queued or retried while offline.

OCPP 1.6 messages

The message models are generated from the official JSON schemas by tools/gen and are Pydantic v2 models. Python attributes are snake_case, the wire names are the spec's camelCase. Requests are <Action>Request and answers <Action>Confirmation; every class has an ACTION class variable. Enums are StrEnums with the spec's values.

Shared datatypes and enums are in ocpp_sdk.v16.types. The 1.6 security extension messages are planned.

from ocpp_sdk.v16 import new_registry
from ocpp_sdk.v16.core import BootNotificationConfirmation, BootNotificationRequest
from ocpp_sdk.v16.types import RegistrationStatus

registry = new_registry()
request = BootNotificationRequest(charge_point_vendor="Acme", charge_point_model="X1")
registry.encode(request)  # {'chargePointVendor': 'Acme', 'chargePointModel': 'X1'}

answer = registry.decode_response(
    "BootNotification",
    {"status": "Accepted", "currentTime": "2025-01-02T03:04:05Z", "interval": 300},
)
assert isinstance(answer, BootNotificationConfirmation)
assert answer.status is RegistrationStatus.ACCEPTED

Incoming messages are validated on decode and outgoing ones on encode. Unknown properties are ignored (real stations send extras); everything else the schemas reject is rejected, plus the clear rules of the spec text: connectorId ranges, meterValue and chargingSchedulePeriod not empty, the first charging period starting at 0, charging limits with at most one decimal, a RemoteStartTransaction profile of purpose TxProfile, unique idTags (ignoring case) in SendLocalList with idTagInfo on every entry of a Full update, and absolute URIs for GetDiagnostics and UpdateFirmware. Naive datetimes are rejected; timestamps are sent in UTC with Z. An invalid incoming call is answered with the CALLERROR code that fits (1.6 spelling, OccurenceConstraintViolation included) and the offending field path.

OCPP 1.6 Charge Point and CSMS

ocpp_sdk.v16.charge_point.ChargePoint is the client and ocpp_sdk.v16.csms.CSMS the server; both are async context managers. Typed methods send each message and return the answer: await cp.boot_notification(BootNotificationRequest(...)) returns a BootNotificationConfirmation; every method takes an optional timeout=. The CSMS calls a station by ID, await csms.reset("CP-1", ResetRequest(...)), or through the session object (csms.ChargePoint) its handlers receive.

  • Handlers. Each feature profile has a handler protocol per side (CoreHandler, FirmwareHandler, LocalAuthListHandler, ReservationHandler, SmartChargingHandler, RemoteTriggerHandler; the Central System receives only Core and Firmware) in ocpp_sdk.v16.charge_point_handlers and ocpp_sdk.v16.csms_handlers. Subclass the matching Unimplemented...Handler and override what you support; the rest answers NotSupported. Methods are on_<message>, sync or async; CSMS handlers get the session first. Wire them with the Config dataclass of each side; a profile left None answers NotSupported, an unknown action NotImplemented.
  • Errors. A handler that raises answers InternalError (the exception text is never sent); raise ocpp_sdk.errors.CallError(code, description) to send a specific code. A CALLERROR from the peer raises CallError in the caller.
  • Offline. Calls fail fast with NotConnectedError, also a call cut off by a lost connection. Nothing is queued or retried, and the station never sends BootNotification or Heartbeat on its own. ChargePoint reconnects per OCPP-J 5.4 (reconnect=Reconnect(...), None turns it off).
  • CSMS. charge_point_ids(), charge_point(id), await for_each(fn) (identity order), on_connect/on_disconnect hooks, await shutdown(timeout=...). A station that reconnects gets a new session; the old session raises NotConnectedError.
import asyncio
from datetime import UTC, datetime

from ocpp_sdk.v16.charge_point import ChargePoint
from ocpp_sdk.v16.core import (
    BootNotificationConfirmation,
    BootNotificationRequest,
    ResetRequest,
)
from ocpp_sdk.v16.csms import CSMS, Config
from ocpp_sdk.v16.csms import ChargePoint as Session
from ocpp_sdk.v16.csms_handlers import UnimplementedCoreHandler
from ocpp_sdk.v16.types import RegistrationStatus, ResetType


class MyCore(UnimplementedCoreHandler):
    async def on_boot_notification(
        self, charge_point: Session, request: BootNotificationRequest
    ) -> BootNotificationConfirmation:
        print("boot from", charge_point.charge_point_id, request.charge_point_vendor)
        return BootNotificationConfirmation(
            status=RegistrationStatus.ACCEPTED, current_time=datetime.now(UTC), interval=300
        )


async def main() -> None:
    async with CSMS(Config(core=MyCore()), port=0) as csms:
        url = f"ws://127.0.0.1:{csms.port}/ocpp/CP-1"
        async with ChargePoint(url) as cp:
            boot = await cp.boot_notification(
                BootNotificationRequest(charge_point_vendor="Acme", charge_point_model="X1")
            )
            print(boot.status, boot.interval)
            # the station has no handlers, so the CSMS' request is answered NotSupported
            try:
                await csms.reset("CP-1", ResetRequest(type=ResetType.SOFT))
            except Exception as exc:
                print(type(exc).__name__, exc)


asyncio.run(main())

OCPP 1.6 transaction message queue

Opt-in and separate from ChargePoint (spec section 3.7): ocpp_sdk.v16.transaction_queue.TransactionQueue(charge_point, ...). Hand it StartTransaction, StopTransaction and MeterValues with start_transaction, stop_transaction and meter_values; it delivers them oldest first and waits while the station is offline (not a failure; ChargePoint.wait_online() is what it waits on). A message the Central System fails to process (CALLERROR, timeout, unusable answer) is tried up to attempts times (default 3), waiting retry_interval (default 60 s) times the number of earlier attempts, then dropped and reported to on_discard(action, request, reason). start_transaction returns a Transaction handle: pass it as transaction= to the messages that belong to the transaction and they get the assigned transactionId when delivered (use any placeholder in the request); if the start is dropped they are dropped too. queue.join() waits until the queue is empty and queue.pending counts what is waiting. The state lives in a TransactionStore: MemoryStore (default) or FileStore(path) (JSON file, replaced atomically on every change, so a restart picks up where it stopped).

import asyncio
from datetime import UTC, datetime

from ocpp_sdk.v16.charge_point import ChargePoint
from ocpp_sdk.v16.core import (
    StartTransactionConfirmation,
    StartTransactionRequest,
    StopTransactionConfirmation,
    StopTransactionRequest,
)
from ocpp_sdk.v16.csms import CSMS, Config
from ocpp_sdk.v16.csms import ChargePoint as Session
from ocpp_sdk.v16.csms_handlers import UnimplementedCoreHandler
from ocpp_sdk.v16.transaction_queue import FileStore, TransactionQueue
from ocpp_sdk.v16.types import AuthorizationStatus, IdTagInfo


class Core(UnimplementedCoreHandler):
    def on_start_transaction(self, charge_point: Session, request: StartTransactionRequest):
        return StartTransactionConfirmation(
            id_tag_info=IdTagInfo(status=AuthorizationStatus.ACCEPTED), transaction_id=42
        )

    def on_stop_transaction(self, charge_point: Session, request: StopTransactionRequest):
        print("stop for transaction", request.transaction_id)
        return StopTransactionConfirmation()


async def main() -> None:
    async with CSMS(Config(core=Core()), port=0) as csms:
        cp = ChargePoint(f"ws://127.0.0.1:{csms.port}/ocpp/CP-1")
        store = FileStore("queue.json")
        async with TransactionQueue(cp, store=store, attempts=3, retry_interval=60) as queue:
            now = datetime.now(UTC)
            # queued while offline: delivered, in order, once the station connects
            tx = queue.start_transaction(
                StartTransactionRequest(connector_id=1, id_tag="TAG", meter_start=0, timestamp=now)
            )
            queue.stop_transaction(
                StopTransactionRequest(meter_stop=10, timestamp=now, transaction_id=0),  # id filled in
                transaction=tx,
            )
            async with cp:
                await queue.join()
                print("assigned", tx.transaction_id)


asyncio.run(main())

Examples

examples/v16/csms.py and examples/v16/charge_point.py are a small Central System and a station that run a transaction against each other over plain ws://:

python examples/v16/csms.py --port 9000 [--password SECRET]
python examples/v16/charge_point.py --url ws://127.0.0.1:9000/CP-1 [--password SECRET]

The test suite runs them against each other, and against the examples of go-ocpp-sdk v1.1.0 in both directions (slow tests; they need the go tool).

Logging

The SDK logs through the standard logging module under ocpp_sdk.* (ocpp_sdk.ocppj.endpoint, ocpp_sdk.transport.server, ocpp_sdk.v16.csms, ...). It never configures handlers or levels, so call logging.basicConfig(level=logging.INFO) or attach your own. The WebSocket library logs as ocpp_sdk.transport.websockets. Message payloads are not logged.

Error handling

All exceptions derive from ocpp_sdk.errors.OCPPError.

ExceptionWhen
NotConnectedErrorNo connection, or the connection was lost during the call. Nothing is queued or retried.
CallTimeoutErrorNo answer within the timeout (30 s from the moment the call was sent).
CallErrorThe peer answered with a CALLERROR (.code, .description, .details); also what a handler raises to send one.
ValidationErrorA request or an answer is invalid (.issues lists field paths).
QueueFullErrorMore than 1,000 calls are waiting behind the outstanding one.
